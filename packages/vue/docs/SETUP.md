# Utensil Design System - Theme Setup

This guide walks through creating your own theme for the Utensil Design System. By the end, you'll have a fully typed theme with custom colors, variants, icons, and a root component to wrap your application.

We'll build an example theme called "Acme" throughout this guide.

## Install

```bash
npm install utensil-vue
npm install vue @fortawesome/fontawesome-svg-core @fortawesome/free-solid-svg-icons @fortawesome/vue-fontawesome
```

`vue` and the FontAwesome packages are peer dependencies, so your app and Utensil share one copy.

`utensil-vue` brings the CSS framework, `utensil-css`, with it and forwards its files at the same subpaths, so import everything from `utensil-vue`. The packages are ESM, built for bundlers such as Vite. Use `"moduleResolution": "bundler"` in your `tsconfig` (the default with `@vue/tsconfig`). There is no barrel file: import each component, composable, and type from its own path (e.g. `utensil-vue/components/button/UtensilButton.vue`), and your bundler includes only the JavaScript and CSS you use.

## 1. Generate Color Scales

Each color in your theme needs a CSS color scale. Utensil provides a generator that produces a full 12-step scale with light mode, dark mode, and alpha variants from a single hex color.

### From utensil.gobistories.com

The quickest way to generate a color scale is from the Utensil reference app at [utensil.gobistories.com](https://utensil.gobistories.com). Use the theme controls to pick a color, then use the menu to copy the generated CSS to your clipboard. Paste it into a new CSS file (e.g., `colors/blue.css`).

### From the CLI

`utensil-vue` installs a `utensil-generate-color` command (it runs on Node):

```bash
npx utensil-generate-color <color> <hex> [options] > path/to/colors/<color>.css
```

For example:

```bash
npx utensil-generate-color blue "#0093ee" > src/acme-theme/colors/blue.css
npx utensil-generate-color red "#e5484d" > src/acme-theme/colors/red.css
```

Run it without arguments to list the options (e.g. `--paper <hex>` to anchor the scales to a theme paper color).

### Programmatically

You can also generate color CSS in code, which is useful for theme builders or dynamic themes:

```ts
import { generateColorCss } from 'utensil-vue/colors/generate-css'

const css = generateColorCss('blue', '#0093ee')
```

Write the output to a CSS file. Repeat for each color your theme needs.

A generated file defines variables for pen, pencil, and paper in both light and dark modes, inside the `utensil` cascade layer:

```css
/**
 * Auto Generated by Utensil Color Generation.
 * Blue
 * color: #0093ee
 * ...generation settings...
**/
@layer utensil, app, utensil-utilities;

@layer utensil {
  :root,
  .light-mode {
    --blue-pen-1: #fbfdff;
    --blue-pen-2: #f4faff;
    /* ...steps 3–12, alpha a1–a12... */
    --blue-pen-contrast: #fff;
    --blue-pen-surface: #f1f9ffcc;
    --blue-pen-indicator: #0093ee;
    --blue-pen-track: #0093ee;
    --blue-pen-brand: #0093ee;

    --blue-pencil-1: #f4fdff;
    /* ...pencil and paper scales... */
  }

  .dark-mode {
    --blue-pen-1: #0c1820;
    /* ...dark mode scales... */
  }

  /* Utility classes to apply this color */
  .blue-pen {
    --pen-1: var(--blue-pen-1);
    /* ...maps all pen variables... */
  }

  .blue-pencil {
    --pencil-1: var(--blue-pencil-1);
    /* ...maps all pencil variables... */
  }

  .blue-paper {
    /* ...maps all paper variables... */
  }
}
```

The header records the settings the file was generated with, so it can be regenerated exactly.

### Choosing Colors

Use basic color names (`blue`, `red`, `green`) for general-purpose colors and semantic names (`brand`, `ocean`) for specific purposes. Utensil includes `gray` by default.

Generate a CSS file for each color your theme will use:

```
acme-theme/
  colors/
    blue.css
    red.css
    orange.css
    green.css
    grey.css
```

## 2. Define Text Themes (Optional)

Utensil provides two base text themes: `ui` (for interface text) and `content` (for reading). You can extend these with your own.

Create a `text-themes.css` file defining a base text theme class and any custom themes:

```css
.text-acme {
  font-family: 'Inter', system-ui, sans-serif;
}

.text-acme h1,
.text-acme h2,
.text-acme h3 {
  font-family: 'Nunito', system-ui, sans-serif;
}

/* Custom article theme for long-form content */
.text-article {
  font-family: Georgia, serif;
  line-height: 1.7;
}
```

Text themes are applied via CSS classes. Your theme root will set the base class, and you can switch themes on specific elements.

## 3. Define the Theme Config

Create an `acme-theme.ts` file that declares your theme's colors, variants, text themes, and icons as TypeScript interfaces. This gives you full type safety and IDE autocomplete throughout your application.

```ts
// acme-theme/acme-theme.ts
import type {
  UtensilColors,
  ThemeConfig,
  UtensilVariants,
  UtensilTextThemes,
  VariantMap,
  TextThemeClasses,
} from 'utensil-vue/theme/utensil-theme'
import { type AcmeIcons } from './acme-icons'

// Declare your colors (must match the CSS files you generated)
interface AcmeColors extends UtensilColors {
  blue: true
  red: true
  orange: true
  green: true
  grey: true
}

// Declare semantic variants that map to colors
interface AcmeVariants extends UtensilVariants {
  primary: true
  secondary: true
  brand: true
}

// Declare any custom text themes beyond the base ui/content
interface AcmeTextThemes extends UtensilTextThemes {
  article: true
}

// Combine into your theme config
export interface AcmeThemeConfig extends ThemeConfig {
  name: 'acme'
  color: AcmeColors
  variant: AcmeVariants
  text: AcmeTextThemes
  icon: AcmeIcons
}

// Map each variant to a concrete color
export const acmeVariantMap: VariantMap<AcmeThemeConfig> = {
  primary: 'blue',
  secondary: 'grey',
  brand: 'blue',
  success: 'green',
  warning: 'orange',
  error: 'red',
  disabled: 'gray',
}

// Specify classes to add when a text theme is used
export const acmeTextThemeClasses: TextThemeClasses<AcmeThemeConfig> = {
  article: 'text-acme text-article',
}

// Default pen and pencil colors
export const acmeDefaultPen = 'blue'
export const acmeDefaultPencil = 'grey'
```

### What Each Part Does

**Name** identifies the theme. When you pass it as the `name` prop on your theme root, Utensil applies it to the theme element as a `<name>-theme` CSS class, so it must be a valid CSS class name — Utensil validates it (`/^-?[A-Za-z_][\w-]*$/`) and throws `Theme name must be a valid CSS class name` otherwise. Kebab-case is fine (e.g. `acme`, `my-app`); it just can't contain spaces or start with a digit. If you add app-level theme CSS, scope it with the matching `.<name>-theme` selector.

**Colors** declare which color scale CSS files are available. Each key must match a generated CSS file (e.g., `blue` matches `blue.css` which defines `.blue-pen` and `.blue-pencil` classes).

**Variants** define semantic color aliases. When a component accepts `color="error"`, the variant map resolves `error` to `red`. The base variants (`success`, `warning`, `error`, `disabled`) are inherited from `UtensilVariants`, these must be mapped in addition to your own.

**Text themes** declare which text theme CSS classes are added when the text theme is applied. Utensil provides `.text-ui` and `.text-content` which you can configure, extend or replace with your own text themes.

## 4. Define the Icon Map

Utensil uses FontAwesome SVG icons. Create an icon map that registers the icons available in your theme.

```ts
// acme-theme/acme-icons.ts
import { faCheck } from '@fortawesome/free-solid-svg-icons/faCheck'
import { faEdit } from '@fortawesome/free-solid-svg-icons/faEdit'
import { faTrash } from '@fortawesome/free-solid-svg-icons/faTrash'
import { faDownload } from '@fortawesome/free-solid-svg-icons/faDownload'
import { faUser } from '@fortawesome/free-solid-svg-icons/faUser'
// ... import each icon you need

import { utensilIconMap, type ExtractIconMap } from 'utensil-vue/theme/utensil-icons'

export const acmeIconMap = {
  ...utensilIconMap, // Include Utensil's base icons
  edit: faEdit,
  trash: faTrash,
  download: faDownload,
  user: faUser,
  // Add any additional icons your app needs
}

// Extract the type from the concrete map
export type AcmeIcons = ExtractIconMap<typeof acmeIconMap>
```

Spread `utensilIconMap` first to include the base icons that Utensil components depend on (check, chevron-down, times, search, etc.), then add your own.

Import icons individually from their deep paths (e.g., `@fortawesome/free-solid-svg-icons/faEdit`) rather than from the package root for better tree-shaking.

## 5. Create the Theme Root Component

A `UtensilThemeRoot` is a `UtensilTheme` with the additional responsibility of loading any CSS and assets needed for a specific theme implementation. All theme props (`pen`, `pencil`, `mode`, `scale`, `variants`, `icons`, etc.) can be used on any `UtensilTheme` anywhere in the tree, but configuration props like `variants`, `icons`, and `textThemeClasses` are typically set once at the root.

You can nest theme roots to embed one theme inside another (e.g., a documentation section using a different theme within a UI app). The theme root is a preconfigured convenience for ensuring everything is loaded and configured for its theme.

```vue
<!-- acme-theme/AcmeThemeRoot.vue -->
<template>
  <!-- @vue-generic {import('./acme-theme').AcmeThemeConfig} -->
  <UtensilThemeRoot
    class="acme-theme-root"
    :mode="mode"
    :pen="acmeDefaultPen"
    :pencil="acmeDefaultPencil"
    :contrast="contrast"
    :reduced-motion="reducedMotion"
    :variants="acmeVariantMap"
    :icons="acmeIconMap"
    :textThemeClasses="acmeTextThemeClasses"
    :radiusScale="radiusScale"
    modal-host
  >
    <slot></slot>
  </UtensilThemeRoot>
</template>

<script setup lang="ts">
/* Ensures your colors and text themes are loaded, see below */
import './acme-css-include'
import type { ThemeMode, ThemeContrast, ThemeReducedMotion, RadiusScaleProp } from 'utensil-vue/theme/utensil-theme'
import { acmeDefaultPen, acmeDefaultPencil, acmeVariantMap } from './acme-theme'
import { acmeIconMap } from './acme-icons'
import UtensilThemeRoot from 'utensil-vue/theme/UtensilThemeRoot.vue'
import { useUtensilIcons } from 'utensil-vue/components/icon/use-utensil-icons'

defineProps<{
  mode?: ThemeMode
  contrast?: ThemeContrast
  reducedMotion?: ThemeReducedMotion
  radiusScale?: RadiusScaleProp
}>()

useUtensilIcons(document.head)
</script>
```

### The CSS Include File

Create a file that imports all your color and text theme CSS. This ensures the CSS is bundled when your theme root is used.

```ts
// acme-theme/acme-css-include.ts
import './colors/blue.css'
import './colors/red.css'
import './colors/orange.css'
import './colors/green.css'
import './colors/grey.css'
import './text-themes.css'
```

### UtensilThemeRoot Props

| Prop               | Purpose                                                  |
| ------------------ | -------------------------------------------------------- |
| `mode`             | Light or dark mode. Defaults to the user's OS preference |
| `pen`              | Default pen color                                        |
| `pencil`           | Default pencil color                                     |
| `variants`         | Your variant-to-color mapping                            |
| `icons`            | Your icon map                                            |
| `textThemeClasses` | Classes applied for each text theme                      |
| `contrast`         | `'normal'` or `'high'`                                   |
| `reducedMotion`    | `'normal'` or `'reduced'`                                |
| `radiusScale`      | Controls overall border radius roundness                 |
| `modal-host`       | Includes a modal host element for teleporting dialogs    |

`mode`, `contrast` and `reducedMotion` are reactive. Changing them will update the theme. Utensil provides a composable for applying user preferences. See `useUserThemePreferences` below.

## 6. Create Typed Component Wrappers

Utensil components that accept theme props (color, icon, variant) are generic. Create typed wrappers so you get autocomplete for your theme's specific colors, variants, and icons.

```ts
// acme-theme/components/AcmeButton.ts
import UtensilButton from 'utensil-vue/components/button/UtensilButton.vue'
import type { AcmeThemeConfig } from '../acme-theme'

export const AcmeButton = UtensilButton<AcmeThemeConfig>
```

```ts
// acme-theme/components/AcmeIcon.ts
import UtensilIcon from 'utensil-vue/components/icon/UtensilIcon.vue'
import type { AcmeThemeConfig } from '../acme-theme'

export const AcmeIcon = UtensilIcon<AcmeThemeConfig>
```

Repeat for any component that has theme props you use frequently. You only need wrappers for components where you pass `color`, `icon`, or other theme-typed props.

The `@vue-generic` comment directive is an alternative if you prefer not to create wrapper files:

```vue
<!-- @vue-generic {import('./acme-theme').AcmeThemeConfig} -->
<UtensilButton color="primary" icon="edit">Edit</UtensilButton>
```

## 7. Use the Theme in Your App

### Load the Layer Order First (Required)

Utensil's CSS is organized into cascade layers (see USAGE.md → "Cascade Layers"). The layer order must be established before any CSS that mentions the layers, so import `utensil-layers.css` as the first line of your application entry point:

```ts
// main.ts
import 'utensil-vue/utensil-layers.css'

import { createApp } from 'vue'
// ...
```

Web component / Shadow DOM consumers get the layer order from `utensil-vue/utensil-css-inline`, a string of Utensil's base CSS that leads with it — inject it into the shadow root before any other stylesheet:

```ts
import utensilCss from 'utensil-vue/utensil-css-inline'

const sheet = new CSSStyleSheet()
sheet.replaceSync(utensilCss)
shadowRoot.adoptedStyleSheets = [sheet, ...shadowRoot.adoptedStyleSheets]
```

Skipping this is unsupported: if a layering problem appears (a utility not applying, consumer CSS not winning), first ensure this import is in place and first.

### Wrap Your Application

Wrap your application with your theme root:

```vue
<!-- App.vue -->
<template>
  <AcmeThemeRoot :mode="mode" :contrast="contrast" :reduced-motion="reducedMotion">
    <RouterView />
  </AcmeThemeRoot>
</template>

<script setup lang="ts">
import AcmeThemeRoot from './acme-theme/AcmeThemeRoot.vue'
import { useUserThemePreferences } from 'utensil-vue/theme/useUserThemePreferences'

const { mode, contrast, reducedMotion } = useUserThemePreferences()
</script>
```

### User Theme Preferences

`useUserThemePreferences` is a composable that manages user preferences for mode, contrast, and reduced motion. It persists selections to `localStorage` and falls back to system defaults.

```ts
const {
  mode, // Ref<'light' | 'dark'>
  toggleThemeMode, // () => void
  contrast, // Ref<'normal' | 'high'>
  toggleContrast, // () => void
  reducedMotion, // Ref<'normal' | 'reduced'>
  toggleReducedMotion, // () => void
} = useUserThemePreferences()
```

You can also use the individual toggle buttons (`UtensilToggleModeButton`, `UtensilToggleContrastButton`, `UtensilToggleReducedMotionButton`) to give users a UI for these settings.

### Using Theme Changes within Your App

Use your typed theme component (based on `UtensilTheme`) to change the theme context anywhere in your component tree:

```vue
<template>
  <div>
    <!-- Use a variant color for an error section -->
    <UtensilTheme pen="error">
      <AcmeCallout>Something went wrong.</AcmeCallout>
    </UtensilTheme>

    <!-- Scale down a toolbar -->
    <UtensilTheme scale="small">
      <Toolbar />
    </UtensilTheme>

    <!-- Or use component color props directly -->
    <AcmeButton color="primary" icon="edit">Edit</AcmeButton>
    <AcmeButton color="error" icon="trash">Delete</AcmeButton>
  </div>
</template>
```

## 8. Test with Vitest

Utensil's compiled components import their own CSS, which Node can't load. Let Vite process the package in your
Vitest config:

```ts
// vitest.config.ts
export default defineConfig({
  plugins: [vue()],
  test: {
    environment: 'jsdom',
    server: { deps: { inline: ['utensil-vue'] } },
  },
})
```

Test components through their public API: props, slots, emitted events and what they `defineExpose`. Utensil ships
production builds, so `wrapper.vm` doesn't carry a Utensil component's setup state or its exposed members. Reach the
exposed API the way a parent's template ref does:

```ts
const list = wrapper.findComponent(UtensilReorderableList).vm.$.exposed as { grab: (id: string) => void }
list.grab('item-1')
```
