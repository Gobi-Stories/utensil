# Utensil Component Audit Checklist

The facts a component built on Utensil is audited against, wherever it is built. Numbers are stable identifiers, so the list has gaps.

Last modified: 2026-10-04

| #   | Pattern                                                                                                                                                                                                                 | Type     | Domain        |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------- |
| 1   | Root element has kebab-case class matching component name (`UtensilButton` → `.utensil-button`)                                                                                                                         | Rule     | Style         |
| 2   | Styles are scoped with root element class                                                                                                                                                                               | Rule     | Style         |
| 3   | Design tokens used for all spacing, sizing, colors                                                                                                                                                                      | Rule     | Style         |
| 4   | No hardcoded colors or legacy variables. Exception: `--black-*` / `--white-*` tokens are correct for components overlaying arbitrary media (images, video) where pen/pencil cannot guarantee contrast                   | Rule     | Style         |
| 5   | Proper TypeScript types for all props                                                                                                                                                                                   | Rule     | Type safety   |
| 6   | Accessibility support with High contrast mode via `.utensil-high-contrast` class, and Reduced motion via `.utensil-reduced-motion`                                                                                      | Rule     | Accessibility |
| 7   | Reduced motion supported for motion animations (not incidental fades) via theme state CSS                                                                                                                               | Rule     | Accessibility |
| 9   | Passes format, lint, typecheck, and test                                                                                                                                                                                | Rule     | Quality       |
| 10  | Focus ring or focus style with `:focus-visible`                                                                                                                                                                         | Rule     | Accessibility |
| 11  | Disabled state styling (`opacity: 0.5`, `pointer-events: none`)                                                                                                                                                         | Pattern  | Accessibility |
| 12  | Keyboard accessible (`tabindex="0"` for non-semantic elements)                                                                                                                                                          | Rule     | Accessibility |
| 13  | ARIA attributes on interactive non-semantic elements (`role`, `aria-pressed`, `aria-disabled`)                                                                                                                          | Rule     | Accessibility |
| 14  | Prefer semantic HTML (`<button>`, `<a>`, `<input>`) over ARIA roles                                                                                                                                                     | Guidance | Accessibility |
| 15  | Generic `Theme extends ThemeConfig` on both `<template>` and `<script setup>` when using theme prop types                                                                                                               | Pattern  | Theme         |
| 16  | `useTheme` only called when component changes pen/pencil/scale via props                                                                                                                                                | Rule     | Theme         |
| 17  | `useTheme` never called without parameters                                                                                                                                                                              | Rule     | Theme         |
| 18  | `ColorProp<Theme>`, `IconProp<Theme>`, `ScaleProp`, `RadiusScaleProp` used for theme-aware props                                                                                                                        | Pattern  | Theme         |
| 19  | No custom props that duplicate theme prop functionality (e.g. `size` when `scale` suffices)                                                                                                                             | Rule     | Theme         |
| 20  | Icon prop uses `IconProp<Theme>` with `v-if` guard on `<UtensilIcon>`                                                                                                                                                   | Pattern  | Theme         |
| 21  | UI variations use `UtensilUIVariation` type (`solid`, `outline`, `surface`, `soft`, `text`, `overlay`, `unstyled`)                                                                                                      | Pattern  | Style         |
| 21b | Provide `unstyled` variation for primitive components where UI Variations are used                                                                                                                                      | Pattern  | Style         |
| 21c | Variations applied via shared `ui-<variation>` classes from `utensil-theme.css` (`` `ui-${variation}` `` in `:class`), not duplicated in component CSS                                                                  | Rule     | Style         |
| 21d | Interactive components combine `ui-<variation>` with `.interactive` modifier class for hover/active states                                                                                                              | Rule     | Style         |
| 21e | Toggle/pressed state uses `.selected` modifier class (not a custom `pressed` class)                                                                                                                                     | Pattern  | Style         |
| 21f | Components using pencil tokens at rest and pen on highlight use `.pencil` modifier (e.g. `{ pencil: !highlighted }`)                                                                                                    | Pattern  | Style         |
| 21g | Disabled interactive elements use shared `.interactive.disabled` style; component-specific overrides only where a different treatment is needed (e.g. recolor)                                                          | Pattern  | Accessibility |
| 22  | Interactive components with state-dependent borders use `box-shadow: inset 0 0 0 1px` to avoid layout shift                                                                                                             | Pattern  | Style         |
| 23  | Regular UI text uses `--pen-a11` / `--pencil-a11` for high contrast compatibility                                                                                                                                       | Guidance | Accessibility |
| 24  | Popover backgrounds use `--panel-solid`                                                                                                                                                                                 | Guidance | Style         |
| 25  | Focus ring: `outline: 2px solid transparent` with `outline-color: var(--pen-8)` on `:focus-visible`                                                                                                                     | Pattern  | Accessibility |
| 26  | Solid variation focus ring uses `outline-offset: 3px`                                                                                                                                                                   | Pattern  | Accessibility |
| 27  | Input focus uses `box-shadow: inset 0 0 0 2px var(--pen-8)`                                                                                                                                                             | Pattern  | Accessibility |
| 28  | Hover does not disable focus style on interactive elements                                                                                                                                                              | Rule     | Accessibility |
| 29  | Elements with own prominent focus style (pen box-shadow/border) skip outline                                                                                                                                            | Guidance | Accessibility |
| 30  | Keyboard-heavy components have `aria-roledescription` and `aria-describedby` with screen reader description for available keys                                                                                          | Rule     | Accessibility |
| 31  | Screen reader text uses `.screen-reader` class; parent has `position: relative`                                                                                                                                         | Pattern  | Accessibility |
| 33  | Related components grouped in same directory with consistent naming                                                                                                                                                     | Rule     | Structure     |
| 34  | Not added to barrel files (direct imports for tree-shaking)                                                                                                                                                             | Rule     | Structure     |
| 35  | Composes existing components, does not duplicate their code                                                                                                                                                             | Rule     | Composition   |
| 36  | Popover components compose primitives (`UtensilPopover`, `UtensilMenu`, `UtensilListbox`, etc.)                                                                                                                         | Pattern  | Composition   |
| 37  | Compound components use `provide`/`inject` for built-in children                                                                                                                                                        | Pattern  | Composition   |
| 38  | Slot scope exposes same API as injected context for custom children                                                                                                                                                     | Rule     | Composition   |
| 39  | API functions named after what they do, not how invoked (`focusItem` not `handleItemHover`)                                                                                                                             | Rule     | Composition   |
| 40  | Named slots (`#trigger`, `#content`) preferred over separate nested wrapper components                                                                                                                                  | Guidance | Composition   |
| 41  | Built-in children are presentational; logic centralized in root component                                                                                                                                               | Pattern  | Composition   |
| 42  | Parent-to-child communication via CSS variables, not `:deep()` selectors                                                                                                                                                | Guidance | Composition   |
| 43  | CSS cvars defined with fallback to design tokens                                                                                                                                                                        | Pattern  | Style         |
| 44  | CSS cvars namespaced with component name (`--side-menu-header-height`)                                                                                                                                                  | Pattern  | Style         |
| 45  | Responsive design handled internally by component                                                                                                                                                                       | Rule     | Behaviour     |
| 46  | Responsive breakpoints use `@container size-container`                                                                                                                                                                  | Pattern  | Behaviour     |
| 47  | Responsive behaviour via CSS cvars (JS reads cvar to determine behaviour)                                                                                                                                               | Pattern  | Behaviour     |
| 48  | `rounded` / `squared` props use `--radius-rounded` / `--radius-squared` tokens                                                                                                                                          | Pattern  | Style         |
| 49  | Absolute positioned elements placed later in DOM rather than using z-index                                                                                                                                              | Guidance | Style         |
| 50  | Theme state selectors (`.light-mode`, `.dark-mode`, `.utensil-rounded`, `.utensil-squared`) targeted for both alternatives                                                                                              | Rule     | Theme         |
| 51  | Nested theme state selectors use unscoped CSS to define local variables                                                                                                                                                 | Pattern  | Theme         |
| 54  | Flex, spacing and shadow utilities from `utensil-utilities.css` used for simple layouts; scoped CSS for complex/responsive layouts                                                                                      | Guidance | Style         |
| 55  | UI standard values followed (radius-3, space-2/3/4 padding, font-size-2, etc.)                                                                                                                                          | Guidance | Style         |
| 56  | Alpha color values preferred for backgrounds and borders (blend across modes)                                                                                                                                           | Guidance | Style         |
| 60  | Logical CSS properties (`inline`, `block`, `start`, `end`) preferred over physical (`left`, `right`, `top`, `bottom`) for padding, margin, border, inset                                                                | Rule     | Style         |
| 57  | Group components use `provide`/`inject` context to configure shared props on children                                                                                                                                   | Rule     | Composition   |
| 57b | Adapter component created when the child can be used independently outside the group (keeps concrete component free of group coupling)                                                                                  | Rule     | Composition   |
| 57c | Missing group context falls back to child defaults — adapter does not throw                                                                                                                                             | Rule     | Composition   |
| 57d | Group component named after child with suffix (e.g. `UtensilButtonGroup`); adapter named with prefix (e.g. `UtensilGroupButton`)                                                                                        | Rule     | Composition   |
| 58  | Composite context precedence: Props > Context > Defaults                                                                                                                                                                | Rule     | Composition   |
| 59  | Generic context interface and injection key when context contains Theme Props (lazy singleton for shared Symbol reference)                                                                                              | Pattern  | Composition   |
| 61  | API documentation created in adjacent file with 'Doc' suffix                                                                                                                                                            | Rule     | Documentation |
| 62  | Font weights for headings/text provided by text UI theme — only override for specific cases (labels, etc.)                                                                                                              | Guidance | Style         |
| 63  | Props declared as an exported interface (`export interface Props<Theme extends ThemeConfig>` with `defineProps<Props<Theme>>()` when it uses theme props), and local types it references exported, so declarations emit | Rule     | Type safety   |
| 64  | Module scope does no work: no I/O, listeners, timers or reactive effects on import; shared state created by the first call (Vue effects in a detached `effectScope(true)`)                                              | Rule     | Behaviour     |
