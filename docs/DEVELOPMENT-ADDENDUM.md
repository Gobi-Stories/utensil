# Component Development Addendum

How components are built in this repository. Read it with the component guide, `packages/vue/docs/DEVELOPMENT.md`,
which holds the principles and patterns every Utensil-style component follows. This addendum adds what is specific to
Utensil's own components and its repository.

## Files and Naming

- Components live at `packages/vue/src/components/<feature>/Utensil<ComponentName>.vue`, with the `Utensil` prefix
  (`UtensilButton` → `.utensil-button`).
- The component's unit test (`Utensil<Name>.test.ts`) and API documentation (`Utensil<Name>Doc.vue`) sit beside it.
- Everything a consumer can import or target is public API (`.claude/CLAUDE.md` → Consumer Compatibility).

## Imports

The guide's examples import Utensil modules by package path (`@gobistories/utensil-vue/theme/utensil-theme`), as a consumer does.
Inside `packages/vue/src`, import them relatively (`../../theme/utensil-theme`): a self-import through `@gobistories/utensil-vue`
resolves to the built package.

## Shared Helpers

Where the guide says to factor a shared helper out of a component directory:

- **Vanilla TS utilities** → `packages/vue/src/lib/<package>/<package>.ts` (alongside `clone`, `equality`, `debouncer`).
- **Vue composables** → `packages/vue/src/composables/`.
- **Domain types and constants** → the same `lib/` package as the related utility.

For example, `mediaTypeToIcon` is shared by `UtensilMediaBadge` and `UtensilTask`-typed wrappers, so it lives at
`packages/vue/src/lib/media-type/media-type.ts`, not under `components/media-badge/`.

## Declarations

`@gobistories/utensil-vue` ships `.d.ts` declarations generated by `vue-tsc`. `bun run build` fails with
`TS4025 … private name 'Props'` when a component's props interface, or a local type it references, isn't exported.

## Module Scope

`packages/vue/src/no-import-side-effects.test.ts` imports every module and fails if one touches storage, listeners,
`matchMedia` or timers on import (`docs/STANDARDS.md` → Module Scope).

## Icons

A new icon goes into Utensil's base icon map when Utensil components need it, or the reference app's theme when only
its demos do. Theme-generic components get a typed wrapper in the reference app's `theme/components/` (e.g.
`ReferenceTask`).

## Theme Colors

Utensil ships a single gray color scale, and its default theme maps the pen, pencil, paper and every variant
(`success`, `warning`, `error`, `disabled`) to it. Consumers always configure a full set of color scales and a variant
map that uses them. Design and judge components for those themes:

- Never decide a design, a state's styling or a fix because one gray looks like another under the default theme. A
  state drawn in the `warning` pen is distinct in every real theme.
- Unit tests that need colors to differ give the component a test theme with a non-gray color (an
  `interface TestThemeConfig extends ThemeConfig` whose `color` adds one, used through a typed `UtensilTheme`),
  rather than asserting on gray.
- UAT in the reference app, which has full color scales and a variant map that uses them (see
  `apps/reference/DEVELOPMENT.md` → Variants).

## Reference App

Every component has demos in the reference app (`apps/reference`, see `apps/reference/DEVELOPMENT.md`):

- Demos use the components typed to the Reference theme, i.e. `ReferenceIcon`, not `UtensilIcon`.
- `apps/reference/src/theme/reference-demos.css` holds the classes shared by all reference pages.
- Labels are hidden by default; apply `.always-visible` to `demo-label` only when the demonstrated feature is not
  obvious without the label.

## Verification

Run `./check` at the repository root before finishing: it formats, lints, typechecks, and tests every workspace. Run
`bun run verify:package` when a change affects what ships (exports, CSS, types, build config, docs, skills): it packs
both packages, installs them into a fresh consumer app, and checks typechecking, tree-shaking and the shipped files.

A **Chrome DevTools MCP** is available for inspecting the running UI (the reference app) - use it to verify styling,
colors, and layout. Judge colors there, in its full theme, never under Utensil's gray default (see Theme Colors).

## Checklist

On top of the guide's checklist:

- [ ] File at `packages/vue/src/components/<feature>/Utensil<Name>.vue`
- [ ] Demos in the reference app, using Reference-typed components
- [ ] A row in `packages/vue/docs/COMPONENTS.md` (`/summarize-component <Name>`)
- [ ] `./check` passes

Audits use `packages/vue/docs/audit-checklist.md` together with `docs/audit-checklist-addendum.md`.
